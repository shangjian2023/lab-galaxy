# 账户、会话与知识边界

## 已实现

- 邮箱注册、登录、退出；首个注册账户成为初始管理员，后续账户默认 `pending`，必须由管理员启用。
- 管理员可启用或禁用其他账户；不能禁用自己，数据库事务保留至少一名可用管理员。禁用账户会删除其全部会话。
- 密码使用带随机 salt 的 scrypt 哈希，参数保存在哈希记录中；接口和日志不返回密码或哈希。
- 随机会话令牌只出现在 HttpOnly、SameSite=Lax Cookie 中；SQLite 只保存 SHA-256 令牌哈希。HTTPS 请求下 Cookie 带 `Secure`。
- 数据库会话有效期 30 天；剩余不足 15 天时，`GET /api/auth/session` 会滑动续期并更新 Cookie。禁用、过期和退出后的会话不可恢复。
- 文档具有 `public`、`private`、`team` 三种可见性，并保存 `owner_id` / `team_id`。列表、详情、分块、全文检索、统计与问答共用相同 SQL 授权条件。
- 匿名用户只能读取公开语料；登录用户可以读取公开语料、本人私有文档及所在团队文档。管理员不因角色而自动获得他人私有原文。
- 问答只对已审核的登录账户开放。未登录请求返回 401，不会调用模型。
- 认证和问答写请求检查 `Origin` / `Sec-Fetch-Site`；登录与注册带进程内限流。只有显式设置 `TRUST_PROXY=1` 时才采信 `X-Forwarded-For`。
- 旧 `/api/v1/*` 部署代理已返回 410，不再把未接入新授权模型的上传或修改请求转发给旧后端。

## API

- `POST /api/auth/register`：注册；首管理员自动登录，其他账户返回待审核说明。
- `POST /api/auth/login`：仅 `active` 账户能建立会话。
- `POST /api/auth/logout`：删除服务端会话并清除 Cookie。
- `GET /api/auth/session`：返回当前账户或 `null`，按需滑动续期。
- `GET /api/auth/users`：管理员读取账户列表。
- `PATCH /api/auth/users/:id`：管理员更新 `pending` / `active` / `disabled` 状态。

账户界面位于 `/account`。首次部署应只在本机创建首个管理员，不能把“零用户时自动成为管理员”的初始化窗口直接暴露到公网。

## 数据表

`users`、`sessions`、`teams`、`team_members` 与文档归属字段定义在 `db/sqlite/001_research_corpus.sql`。应用首次连接已有语料库时会幂等补充这些表和列，原有 50 份文档保持 `public`。

会话令牌示例结构不会写入文档或测试；测试只断言 Cookie 属性和数据库中的哈希格式，不输出令牌值。

## 当前边界

- 团队协作 UI、邀请、角色编辑和个人资料修改尚未实现；`teams` 表与团队授权规则已建立并有隔离测试。
- 新版上传和持久任务尚未开放，因此普通用户暂时不能从界面创建私有文档。
- 问答历史尚未持久化；切换或退出账户会清空当前页面中的回答，避免上一账号证据留在界面中。
- 限流是单进程内存实现，不能替代多实例部署的分布式限流、WAF 或 abuse 监控。
- 尚无邮件验证、密码找回、MFA、审计日志和加密的人工智能配置管理。
- 当前数据库仍是 SQLite；不得据此声称 PostgreSQL/pgvector 已部署。
